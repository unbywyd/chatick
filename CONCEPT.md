# Chatick — концепция продукта

> Проектное рабочее пространство, где чат — интерфейс, а ИИ — диспетчер.
> Домен: **chatick** · Статус: концепция / pre-MVP · Дата: 2026-07-23

---

## 1. Проблема

Типичная ситуация в небольшой компании:

- Задачи живут в таск-менеджере (Monday / самописная система), а общение — в WhatsApp.
- **Нет единого источника правды**: тут удобно одно, там другое.
- Статус пишется в системе задач, но чтобы «дошло быстрее» — дублируется в WhatsApp.
- Документы шлют в WhatsApp, где они теряются; в системе задач их никто не ищет.
- Одни и те же вопросы задают по многу раз — никто не помнит, что уже спрашивал.
- Постоянный пинг-понг между системами, сообщения теряются, контекст расползается.

**Корень проблемы:** общение и работа разорваны по разным инструментам, и ни один из них не «помнит» за людей.

## 2. Решение

**Chatick** — приложение (web + Electron для Win/Mac), где:

- **Проект = группа.** Создал проект → пригласил сотрудников → есть чат и рабочее пространство.
- **Всё управляется через чат.** Задачи, файлы, статусы — можно руками через UI, но основной сценарий — через чат.
- **В чате сидит ИИ-диспетчер**, через которого проходят все сообщения.

### ИИ-диспетчер (ключевая фича)

Сообщение, отправленное в чат, **визуально появляется сразу, но физически проходит через ИИ**, который:

1. **Переводит** — каждый пишет на своём языке, остальные читают на своём.
2. **Дедуплицирует вопросы** — «на это уже отвечали, вот ответ/ссылка» вместо повторного флуда.
3. **Уточняет** — если сообщение непонятно, ИИ задаёт вопросы автору до отправки (с контролами подтверждения).
4. **Маршрутизирует статусы** — «я закончил X» превращается в обновление задачи, а не во флуд в чате.
5. **Отвечает сам**, когда ответ есть в переписке / задачах / файлах — человека не дёргают.

Агрессивность ИИ настраивается per-group: от «только перевод» до полного фильтра.

**Главный магнит продукта: спросить у проекта быстрее, чем спросить у человека.**

### Два режима чата

- **Режим группы** — пишешь всем участникам (через ИИ-диспетчер).
- **Режим ИИ** — личный диалог с ИИ проекта (вопросы, поиск, управление задачами).

Разделение ответственности: понятно, когда ты говоришь с командой, а когда с ассистентом.

### Личное общение → WhatsApp

Chatick **не заменяет WhatsApp и не строит DM**. Личное — не наша зона:
клик на участника → «Написать в WhatsApp» → deep link `wa.me/{phone}`.

Граница дисциплинирует: рабочее — в проекте (ищется, помнится), личное — в WhatsApp.

### Agent-native: HTTP API + MCP-сервер

У проекта обязан быть **HTTP API и MCP-сервер** — чтобы работать с проектом из Claude Code / любого агента, **не выходя из редактора**:

- «что нового по проекту?» → агент читает чат и задачи
- «пометь TASK-42 done и напиши в чат, что готово к ревью» → статус обновлён, сообщение ушло в группу от имени разработчика
- Менеджер спрашивает статус в чате → ИИ проекта отвечает сам по свежим данным

MCP-сервер — тонкая обёртка над тем же API, что использует фронтенд. Авторизация — персональный API-токен, все действия от имени пользователя. Внутренний ИИ-диспетчер использует **те же tools**, что и внешние агенты — один слой инструментов.

## 3. Интерфейс

Layout **40 / 60**:

```
┌────────────────┬──────────────────────────────┐
│                │  [О проекте][Задачи][Файлы]  │
│     Чат        │  [Кредишены]                 │
│   (40%)        │                              │
│                │      Контент таба (60%)      │
│  режим: группа │                              │
│  / ИИ          │                              │
└────────────────┴──────────────────────────────┘
```

Табы проекта:
- **О проекте** — описание, участники, настройки, настройки ИИ
- **Задачи** — минимальный таск-менеджер: задачи, статусы, ассайни, комменты (комменты = ветки в чате)
- **Файлы** — файлы проекта в одном месте, ИИ находит по запросу
- **Кредишены** — доступы/креды проекта

Всё в табах управляется и руками, и через чат — но чат первичен.

## 4. Скоуп MVP

1. Проект = группа, приглашения участников
2. Чат: режим группы / режим ИИ
3. ИИ-диспетчер: перевод, дедуп, уточнения, статусы → задачи
4. Табы: О проекте, Задачи, Файлы, Кредишены
5. Личное → WhatsApp (deep link, без API WhatsApp)
6. HTTP API + MCP-сервер с API-токенами
7. Web-версия; Electron — обёртка следом

### Отложено (сознательно)

| Фича | Почему отложена | Когда |
|---|---|---|
| **Интеграция с GitHub / индексация кода** | Несоразмерно сложно для MVP: OAuth/App, вебхуки, индексация, безопасность приватных реп. Ядро ценности работает без кода. Агент в редакторе и так видит код локально — ему нужен доступ к проекту через MCP, а не проекту к коду. | Итерация 2: сначала просто вебхуки (PR/деплой → в чат), потом поиск по коду |
| DM (личные чаты внутри) | Личное → WhatsApp. Минус огромный кусок работы. | Возможно никогда |
| Мобильное приложение | Web покрывает старт; но менеджеры живут в телефоне — понадобится рано | После валидации MVP |
| Интеграции с чужими таск-менеджерами | Ломают «единую правду» — свой минимальный таск-менеджер в ядре | По запросу |

### Архитектурный принцип на вырост

ИИ отвечает на основе **источников контекста проекта** (переписка, задачи, файлы). Репозиторий, вебхуки и прочее позже добавляются как ещё один источник — интерфейс не меняется.

## 5. Риски и как их закрываем

| Риск | Митигция |
|---|---|
| Задержка сообщений ИИ-фильтром бесит людей | Визуально сообщение мгновенно; ИИ вмешивается только когда уверен. Блокирующий режим — опция per-group |
| Рабочие вопросы утекают в личку WhatsApp | ИИ в группе отвечает быстрее человека в личке; кнопка WhatsApp фреймится как «личное» |
| Стоимость LLM на каждое сообщение | Считать unit-экономику; дешёвые модели для маршрутизации, дорогие — для ответов |
| «Все сообщения читает ИИ» — приватность | On-prem / BYO-key вариант в roadmap |
| Миграция команды в новый инструмент | Продаём не «мессенджер», а рабочее пространство (vs зоопарк Monday+WhatsApp+Drive); внедрение сверху вниз; email-дайджесты как крючок |

## 6. Позиционирование

Не «замена WhatsApp» (война, которую не выиграть), а **рабочее пространство проекта**:
конкурент — не мессенджер, а связка «таск-менеджер + WhatsApp + облако файлов».

Дифференциаторы:
1. ИИ-**шлюз** между людьми (не «помощник рядом», как у всех)
2. Перевод на лету — критично для многоязычных команд
3. Дедуп вопросов — «уже спрашивали, вот ответ»
4. Agent-native: MCP из коробки, работа с проектом из редактора
5. Заказчик №0 — мы сами: инструмент решает нашу собственную боль
