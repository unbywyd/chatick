# Безопасность данных в Chatick

Документ отвечает на вопрос «что будет с нашими данными» — фактами, а не
обещаниями. Написан для тех, кто решает, можно ли доверить платформе рабочую
переписку и файлы команды.

> **Сразу о главном.** Стопроцентной гарантии не даёт никто — ни AWS, ни Google,
> ни мы. Обещать её значит соврать. Ниже — что именно защищает данные, где
> границы этой защиты и что произойдёт, если что-то всё-таки случится.

---

## 1. Где физически лежат данные

| | |
|---|---|
| Серверы | Германия (Hetzner), юрисдикция ЕС и GDPR |
| База данных | PostgreSQL на том же сервере, наружу не смотрит |
| Файлы | Cloudflare R2 (S3-совместимое хранилище) |
| Резервные копии | локально + отдельно в R2 |

Компания может подключить **своё хранилище S3/R2** — тогда файлы вообще не
попадают на нашу сторону, а лежат в её собственном бакете.

## 2. Доступ к базе

База слушает нестандартный порт и закрыта файрволом: политика по умолчанию —
`deny incoming`. Открыто только для перечисленных подсетей администратора.
Из интернета подключиться к базе нельзя.

Проверяемо: `ufw status` на сервере, `Default: deny (incoming)`.

## 3. Шифрование

**Пароли** не хранятся. Только хеш scrypt со случайной солью; сравнение
идёт `timingSafeEqual` — так время ответа не подсказывает подбирающему,
насколько он близок.

**Секреты в разделе «Ресурсы»** (пароли к панелям, API-ключи) шифруются
**AES-256-GCM** до попадания в базу. Даже с полным доступом к базе прочитать
их нельзя без ключа, который лежит отдельно, в переменных окружения.

Значения секретов **никогда не передаются ИИ** — ни своему, ни внешнему
ассистенту через мост. Ассистент может их сохранить, но не может прочитать.

**Резервные копии** шифруются паролем, который задаёт сама компания
(AES-256-GCM поверх архива). Без него копия бесполезна даже для нас.

**Транспорт** — HTTPS везде, включая WebSocket.

## 4. Резервное копирование

Две независимые схемы, обе по расписанию:

| Что | Когда | Куда | Хранение |
|---|---|---|---|
| Дамп всех баз | ежедневно 03:07 | локальный диск | 14 дней |
| Архив всех баз | ежедневно 03:30 | Cloudflare R2 | ротация |

Копия в R2 лежит **вне сервера**: потеря машины целиком не означает потерю
данных.

Проверяемо по журналу: `/var/log/postgres-backup-r2.log`, строка `run OK` и
имя выгруженного архива.

## 5. Что можно забрать с собой

- **Полный экспорт и импорт** всей системы — компании, проекты, задачи, чат,
  документы, файлы. Не «выгрузка в CSV», а состояние целиком.
- **Открытый исходный код.** При желании система разворачивается на серверах
  компании, и мы перестаём быть звеном вообще.

Это и есть настоящая гарантия: не «мы обещаем не потерять», а «вы в любой
момент забираете всё и уходите».

## 6. Разграничение доступа

- Роли на уровне компании: admin / manager / member.
- Права на уровне проекта по доменам (задачи, файлы, ресурсы, документы,
  заметки): none / read / write / crud.
- Членство проверяется **живым запросом к базе на каждом обращении**, а не по
  токену. Человека исключили из проекта — доступ пропадает сразу, а не когда
  истечёт его токен.
- Личность так же сверяется с базой: удалённый пользователь не может ходить
  по системе со старым токеном.

## 7. Доступ ИИ-ассистента

Внешний ассистент (Claude Code и подобные) подключается через мост:

- действует **от имени человека**, который подтвердил доступ, и строго в
  границах его прав;
- каждое действие попадает в журнал проекта под именем этого человека;
- подключение — туннель: закрыли, и доступа больше нет. Постоянных токенов
  нет, утекать нечему;
- **значения секретов недоступны** ассистенту в принципе;
- **удалять проекты и компании ассистент не может** — это оставлено людям.

## 8. Опасные действия

Удаление проекта или компании уносит всё связанное, включая файлы. Поэтому:

- живёт в отдельной, явно помеченной опасной зоне;
- требует подтверждения;
- после выполнения **письмо каждому участнику**;
- удалённые задачи, файлы, документы и заметки восстановимы **7 дней**.

## 9. Что журналируется

- Журнал активности проекта: кто что менял и когда. Хранится, доступен для
  чтения, изменению не подлежит.
- Отдельный аудит доступа к секретам: каждое раскрытие значения записывается.

## 10. Где границы — честно

Чего эта защита **не** покрывает:

- **Компрометация машины администратора.** Доступ к серверу идёт по ключу с
  ограниченных подсетей, но человек с этим ключом может всё.
- **Ошибка человека внутри компании.** Роли ограничивают, но участник с
  правами `crud` может удалить то, что ему доверили. Отсюда семь дней на
  восстановление.
- **Мы в бете.** Продукт используется каждый день, но он молодой; в нём есть
  и будут ошибки. Именно поэтому бэкапы и полный экспорт стоят на первом
  месте, а не в конце списка.

---

## Как проверить самим

Всё, что написано выше, проверяется, а не принимается на веру:

```bash
# база закрыта снаружи
ufw status                       # Default: deny (incoming)

# бэкапы реально уходят
tail /var/log/postgres-backup-r2.log     # run OK + имя архива

# код открыт
https://github.com/unbywyd/chatick
```
