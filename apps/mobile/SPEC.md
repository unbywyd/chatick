# Chatick Mobile — техническое задание

Приложение под Android, с прицелом на iOS из той же кодовой базы.

> **Это ТЗ, а не отчёт о сделанном.** Ничего из описанного пока не написано.
> Раздел «Состояние» внизу отмечает, что готово.

---

## 1. Чего мы НЕ делаем

- **Не оборачиваем веб в WebView.** Ради чата и голосового ввода нужен
  нативный слой: WebView даёт заметную задержку в списках сообщений и не
  пускает к системному распознаванию речи.
- **Не делаем файловый менеджер** — отложено. Просмотр файла, присланного в
  чат, обязателен.
- **Не делаем вход по OTP на почту.** Только Google, как в десктопе.

## 2. Технологии

| | | Почему |
|---|---|---|
| **React Native + Expo** | каркас | Одна кодовая база под Android и iOS. Expo снимает возню с нативной сборкой, а `expo-dev-client` оставляет возможность подключать нативные модули |
| **TypeScript** | язык | Как во всём монорепо |
| **TanStack Query 5** | данные | Тот же слой, что в `apps/app` — привычные ключи и инвалидация |
| **expo-speech-recognition** | речь → текст | Системное распознавание Android и iOS: бесплатно, без наших серверов и без отправки голоса третьим лицам. Уже проверено в бою на другом проекте (`D:\ment_verse`) — берём оттуда, а не подбираем заново |
| **expo-auth-session** | вход Google | Системный браузер, а не встроенное окно: Google запрещает OAuth во встроенных webview |
| **expo-secure-store** | токен | Хранилище ключей ОС, а не `AsyncStorage` |
| **expo-notifications** | пуши | На потом, но закладываем сразу |

Живёт в `apps/mobile/`, подхватывается корневым `pnpm-workspace.yaml`.

## 3. Что берём с сервера как есть

Мобильное приложение **не требует новых сущностей**: API уже отдаёт всё нужное.
Токен — сессионный, **уровня компании**, как в десктопе: отдельного входа в
проект нет, доступ ко всем проектам компании сразу.

```
POST /api/v1/auth/google            вход (системный браузер)
GET  /api/v1/auth/me                кто я
GET  /api/v1/companies              мои компании
POST /api/v1/companies              создать компанию
GET  /api/v1/projects               проекты компании
GET  /api/v1/messages               чат проекта
POST /api/v1/messages               отправить
GET  /api/v1/inbox                  уведомления по всем проектам
GET  /api/v1/tasks                  задачи
GET  /api/v1/notes                  заметки
GET  /api/v1/resources              ресурсы (значения секретов не отдаются)
GET  /api/v1/activity               история проекта
GET  /api/v1/my/time/running        идущий таймер
POST /api/v1/time/start | /stop     трекер
WS   /ws?token=…                    живые события
```

Новое понадобится только под пуши (регистрация токена устройства) — не в
первой версии.

## 4. Экраны

### 4.1. Сплеш
Иконка Chatick на тёмном фоне. Пока проверяется сохранённый токен.

### 4.2. Вход
- Заголовок и подзаголовок как на макете.
- Одна кнопка — **Sign in with Google**.
- Открывается системный браузер (`expo-auth-session`), возврат по deep link.
- Токен в `expo-secure-store`.
- Ошибку показываем текстом, вход можно повторить сразу — **кнопка не
  блокируется** (в десктопе это уже стоило нам залипания на десять минут).

### 4.3. Выбор компании — обязательный шаг
Сразу после входа. Ровно как в десктопе:
- список компаний, где человек состоит;
- если компаний нет — мастер создания: **компания + первый проект** одним
  потоком;
- выбранная компания запоминается, но её можно сменить.

**Без выбранной компании дальше не пускаем**: токен действует на всю компанию,
и без неё непонятно, чьи проекты показывать.

### 4.4. Проекты (главный экран)
Список проектов как список чатов:

```
[аватар] AppName                          [32]
         Последнее сообщение…          2 мин назад
```

Сверху:
- аватар (по нажатию — профиль и смена компании);
- **колокольчик** с числом непрочитанных по всем проектам;
- **карусель уведомлений** — горизонтальные карточки: кто, о чём, из какого
  проекта. Нажатие ведёт прямо к источнику.
- **таймер**: идущий трекер с выбором проекта, как в панели трея. Пуск, пауза,
  стоп.

Внизу — **Создать проект**.

### 4.5. Проект
Шапка: логотип, название, «8 участников, 5 онлайн».

**Три вкладки**: `ИИ` · `Чат проекта` · `Мои задачи`.

Ключевое требование: **уведомления других проектов не теряются**. Под шапкой —
строка чипов с новыми уведомлениями любых проектов, чтобы уйти в соседний
проект, не возвращаясь на список.

### 4.6. Два уровня ИИ
- **Чат проекта** — общий, там же работает диспетчер.
- **ИИ-чат** — приватный разговор с ассистентом проекта, никто больше его не
  видит. Отдельная вкладка, отдельная история.

Различие должно быть видно глазами: спутать приватный вопрос с сообщением всей
команде — дорогая ошибка.

### 4.7. Голосовой ввод — обязательно
Кнопка микрофона в поле сообщения. Держим — говорим — отпускаем, текст
подставляется в поле **до отправки**, с возможностью поправить.

Через `expo-speech-recognition`: системное распознавание, без наших серверов и
без отправки записи наружу. Язык — из настроек проекта.

**Микрофоном владеет один модуль.** На `D:\ment_verse` уже наступили на эти
грабли: рядом с распознавателем работал отдельный рекордер `expo-audio`, они
дрались за микрофон, рекордер побеждал — и распознаватель слышал тишину, а
каждое сообщение уходило с пустым текстом. `expo-speech-recognition` умеет
сохранять аудио сам (`recordingOptions.persist`), поэтому и файл, и текст
берутся с одного открытого микрофона.

Текст — «сколько получилось»: не распозналось — отдаём голос без текста, а не
теряем сообщение целиком.

Работает в обоих чатах.

### 4.8. Боковая панель проекта
Открывается нажатием на логотип проекта в шапке:
- **Ресурсы** — список, значения секретов не показываем (как в вебе: только по
  явному запросу и с записью в аудит);
- **Заметки** — лента с прокруткой;
- **История** — журнал активности проекта, с прокруткой;
- участники;
- выйти в список проектов.

### 4.9. Файлы
Менеджера нет. **Просмотр вложения из чата обязателен**: картинки с зумом,
остальное — системным просмотрщиком.

## 5. Требования, не привязанные к экрану

- **Живые события** — тот же WebSocket `/ws`. При возвращении в приложение
  соединение поднимается сразу, а не по нарастающей паузе, и следом
  перечитываются уведомления с задачами: за время сна события ушли в никуда.
- **Тёмная тема** — основная, как на макетах.
- **Языки** — русский, английский, иврит (RTL). Строки берём из `apps/app`,
  не заводим второй набор переводов.
- **Показываем только то, что касается человека** — правило платформы: бейджи
  и уведомления не растут от чужой активности.
- **Ассистент не удаляет** — мобильное приложение тем более: удаление проектов
  и компаний остаётся на десктопе.

## 6. Порядок работы

1. Каркас Expo, вход через Google, хранение токена, сплеш.
2. Выбор и создание компании, список проектов.
3. Чат проекта: сообщения, вложения, WebSocket.
4. Голосовой ввод.
5. Вкладки: ИИ-чат, Мои задачи.
6. Карусель уведомлений и чипы других проектов.
7. Таймер.
8. Боковая панель: ресурсы, заметки, история.

Каждый шаг заканчивается собираемым APK — так видно, что работает, а что нет.

## 7. Репозиторий открыт

Монорепо публичное. Значит:
- никаких ключей и токенов в коде — всё через переменные окружения;
- `google-services.json` и keystore **не коммитим**, добавляем в `.gitignore`;
- ID клиента OAuth для мобильного приложения — публичное значение, но secret к
  нему в репозиторий не кладём.
